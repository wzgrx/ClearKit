# 07 · 从零到发版

按阶段做，每段有过关条件。每个阶段的检查清单在 [checklists/](checklists/)。

## 阶段 1：调研上游

1. 找同类模块（GitHub 搜宿主名 + Xposed / LSPosed / 净化 / 去广告），克隆到 `~/ref/<宿主>-upstream/`。
2. **每个仓库都完整分析**：设置项清单、实现方式、最近的 PR 和 issue。不要只看 README。
3. 写对照文档 `docs/upstream/<日期>-review.md`：每个上游一节，分“我们更强 / 我们没有 / 也有的问题”。
4. 写任务清单 `docs/upstream/TASKS.md`：编号（U01…）、来源、要做什么、状态。
5. 注意上游的**空开关**（有设置项、代码里没人读）和**绕过付费**的功能：前者照做时自己实现，后者不做。

过关：对照文档和任务清单都有，维护者看过并选定要做的。

## 阶段 2：品牌

1. 起名（[01](01-naming.md)）→ 维护者确认。
2. 定强调色（[02](02-color.md)）。
3. 设计图标（[03](03-icon-design.md)）→ 出图（[04](04-icon-pipeline.md)）→ 维护者确认 → 接进项目，母版和 JSON 放 `docs/brand/`。

过关：名字、颜色、图标都确认；`report.txt` 安全区通过。

## 阶段 3：符号和版本矩阵

1. 收集宿主安装包：每个渠道最新版 + 上一版，放 `$<宿主>_APK_DIR/<渠道>-<versionCode>/base.apk`。
2. 反编译（jadx）到 `~/projects/<宿主>-src/<渠道>-<versionCode>/`，找 Hook 点用。
3. 写 SymbolGroup，生成内置表和版本矩阵。

过关：每个内置版本 `0 missing`；DexKit 一致性测试通过（手机现场适配和电脑生成的表一样）。

## 阶段 4：设置盘点和示意图

按 [05](05-live-preview-ui.md) 做：列全部设置 → 按“改了以后哪里变”分类 → 每页一张示意图 → 专属预览。

过关：覆盖测试通过（每项用户设置都画进了示意图）；绑定合法；一页一图。

## 阶段 5：功能

按 [06](06-module-architecture.md) 写。一个功能一个提交，提交信息写清楚做了什么、各版本命中了什么。

过关：单测通过；新加的查询在每个内置版本唯一命中。

## 阶段 6：门禁

`scripts/verify.sh`：全部单测（含真实安装包的符号表校验、DexKit 一致性）+ lint（警告也算失败）+ 用长期签名打的 release 包 + 证书和内容检查。

- 改界面时先在电脑上看截图（Robolectric 渲染）再上真机。
- 签名口令不落盘、不入库（从系统凭据解密进环境变量）；签名私钥不提交。

过关：`verify.sh` 通过。

## 阶段 7：真机

- 共用的测试机**先看前台**：只有桌面、宿主、本模块在前台才动手；别的应用在前台说明有人在用，先问。
- 冒烟：`scripts/smoke.sh <设备>`（装模块、重启宿主、读 LSPosed 日志，汇总生效功能数、失败、崩溃）。
- 每个新功能在真机上验：开开关 → 操作 → 截图或日志确认 → **还原开关**。
- 测试留下的文件、记录、计数都删掉。
- 会替账号操作的功能不打开。

过关：冒烟通过；每个新功能有真机结论（通过 / 没碰到可测的场景，写明哪种）。

## 阶段 8：发版

1. `CHANGELOG.md` 加一节：用用户能看懂的话写改了什么、为什么；没做的、没测到的也写。
2. `gradle.properties` 升版本号（versionCode 只增不减）。
3. 门禁通过后提交、推送。
4. **发 GitHub Release 前问维护者**（除非维护者说过可以直接发）。
5. `gh release create v<版本> --repo <仓库> --target <提交> -F <说明> <安装包>`；安装包是长期签名的 release APK。
6. 装到测试机上。

过关：Release 页有安装包和说明；测试机上是新版本。

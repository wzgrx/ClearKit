# 00 · 家族总览

## 净界是什么

“净界”是一组 LSPosed / Xposed 模块（libxposed API 102），每个模块服务一个 App（叫“宿主”）：去广告、精简界面、过滤内容、
增强播放和下载。每个模块自己有一个 Android App（设置界面、诊断、备份），在宿主里也有入口和设置窗。

它们**看起来像一家**：同样的命名方式、同样的图标风格、同样的设置界面（实物预览）、同样的代码结构和发版流程。
它们**又各有特色**：宿主不同，强调色、图标意象、首页那句统计、专属预览各不一样。

## 统一的和各自的

| 统一（照抄，不要改） | 每个模块自己定 |
|---|---|
| 命名格式：宿主昵称 + “净界” | 宿主昵称（两个字） |
| 图标风格：水晶玻璃、暖色主体 + 晶透蓝第二面 + 乳白记号 + 外发光（[03](03-icon-design.md)） | 图标里画什么（宿主的意象） |
| 图标底色：浅色 `#F5F2EF`、深色 `#303030`；前景内缩 22% | 主体和第二面的具体颜色 |
| 界面：版式、组件、字号、间距、圆角、状态色、深浅色 | 强调色（一个种子色，自动出浅色 / 深色两套，见 [02](02-color.md)） |
| 设置界面：实物预览（示意图点块改设置，[05](05-live-preview-ui.md)） | 每页示意图画的内容；1–2 个专属预览 |
| 首页结构：大状态卡 + 一句统计 + 常用开关 + 最近改动 | 那句统计怎么说（“这周帮你挡下 1,284 条”“省下 21 分钟”） |
| 代码分层、功能运行时、熔断和崩溃保护、桥接、诊断（[06](06-module-architecture.md)） | 符号定义、功能代码 |
| 门禁、截图测试、真机冒烟、发版流程（[07](07-workflow.md)） | 支持的宿主版本 |

**判断标准**：用户同时装两个净界模块，打开它们的 App，应该觉得是同一个团队做的；只看图标，应该一眼认出各自对应哪个 App。

## 做一个新模块的阶段

每个阶段有明确的“过关条件”，没过不进下一阶段。细节见 [07-workflow.md](07-workflow.md)，给 AI 的逐步版本见 [08-ai-playbook.md](08-ai-playbook.md)。

| 阶段 | 做什么 | 过关条件 |
|---|---|---|
| 1 调研 | 收集同类上游模块，逐个读源码和 issue，列“有 / 没有 / 更强” | `docs/upstream/` 下有对照文档和任务清单 |
| 2 品牌 | 起名、定强调色、出图标 | 名字确认；图标 `report.txt` 安全区通过，四种桌面效果都看过 |
| 3 符号 | 收集宿主安装包，用 DexAdapt 写查询，生成内置符号表 | 每个内置版本 `0 missing` |
| 4 设置盘点 | 列全部设置，每页设计示意图 | 覆盖测试通过：每项设置都画进了某张示意图 |
| 5 功能 | 写 Hook 功能，能写成纯函数的写单测 | 单测通过 |
| 6 门禁 | 单测 + lint（警告算失败）+ 签名的 release 包 + 截图 | `scripts/verify.sh` 通过 |
| 7 真机 | 冒烟、逐项验证，测完把改过的设置还原 | 冒烟通过，每个新功能有真机结论 |
| 8 发版 | 更新日志、版本号、打标签、上传安装包 | GitHub Release 有安装包；发版前问过维护者 |

## 参考实现

- 哔哩净界（wzgrx/BiliClear）：最完整的参考，实物预览、按用途分类、去广告兜底、观看 / 搜索历史都在这里。
- 红薯净界（wzgrx/ShuClear）：第二个照这套做的模块，验证了共享部分真的通用。
- DexAdapt（wzgrx/dexadapt）：通用的版本适配库，所有模块共用。

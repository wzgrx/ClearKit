# 实物预览设计方法

一句话：**不让用户想象“开了会怎样”，直接把目标界面画出来，点哪块改哪块，改了马上看到。**
示意图既是预览也是控件；列表退居第二（“列表”视图），用来看完整说明。

来源：哔哩净界（BiliClear）5.4–6.2 的实践，用户评价“天才设计”，并要求“全部功能都这样、信息密度要高、高效”。
参考实现见文末。

---

## 1. 先盘点，再设计

1. **列出全部设置**（开关、单选、多选、数值、文字、名单），记下每项属于哪个页面。
   - 写一个临时单测或脚本，把“设置 → 页面 → 有没有预览”打印出来，按页面分组。
   - 只排除两类：内部状态（令牌、位置、缓存这类不给用户改的），以及标着“即将支持”、还没实现的。
2. **按“改了以后哪里变”分类**：

   | 效果 | 画法 | 例子 |
   |---|---|---|
   | 藏掉某个东西 | **划掉** + ✕（灰底、删除线） | 开屏广告、底栏某项、评论区广告卡 |
   | 改了样子或行为 | **加标签**（“自动展开”“按正则”“用上次的”） | 简介自动展开、锁屏暂停 |
   | 新加一个东西 | **“+”块**：关时虚线灰字，开时强调色 | 3 倍速档、长按菜单里的“保存原图” |
   | 一个数值或文字 | **数值块**：块里直接写当前值 | “双击 每次跳 10 秒”“服务器 未设置” |
   | 只是陪衬 | **浅色无边框块**，不能点 | 卡片里的“视频”“简介” |

3. **决定每页的示意图长什么样**：照目标界面的真实顺序和结构画（页签条、深色的视频画面、画面上的浮层、带标题的分组、一行并排）。
   不画像素级，只画“有哪些块、大致在哪”。名字用目标界面里的叫法。

## 2. 专门预览（示意图之外的补充）

有些效果用块画不清楚，配专门的预览卡（也都要实时跟着设置变）：

- **样例信息流**：过滤、名单类规则，拿用户**最近真实刷到的内容**试——会藏的划掉并写原因，顶上写“最近 60 条里会藏 9 条”，命中一半以上提醒“规则可能太宽”。
  - 编辑名单时，每条后面写“最近命中 N 条”。
  - 样例只记屏幕上本来就显示的字段，只存本机，可关、可清空。
- **前后对比**：分享文字（去掉的参数用删除线）、数字格式、界面缩放（两部小手机，色觉辅助套真实的颜色矩阵）。
- **时间轴 / 流程**：片段跳过、播放结束后的流程、清晰度阶梯（请求哪一档，退到哪一档）。
- **证据卡**：网络、解锁这类看不见的功能，写“这周起作用了 N 次”；还没起作用时说清楚，别显示 0。
- **实测**：节点测速，画成按快慢排的条，点一条就选它。

## 3. 统一的数据模型（一份结构，多端渲染）

示意图写成**纯数据**，放在不依赖界面框架的公共模块里。App（Compose）和宿主里的设置窗（View）按同一份结构画，不各写一套。

```kotlin
data class Bind(
    val setting: Setting<*>, val option: String? = null,   // 开关 / 多选的一项 / 单选的一项
    val requires: BoolSetting? = null,                     // 依赖的总开关：关着不算生效，点块时一起打开
    val minKeep: Int = 0, val maxKeep: Int = Int.MAX_VALUE, // 多选上下限（至少留一个、最多 4 个）
)
enum class Effect { HIDE, MARK, ADD, VALUE }
enum class Style { PLAIN, MEDIA, OVERLAY, ROW, GROUP, TABS }
data class Block(
    val label: String, val bind: Bind? = null, val effect: Effect = Effect.HIDE, val mark: String? = null,
    val style: Style = Style.PLAIN, val children: List<Block> = emptyList(),
    val zero: String? = null, val fmt: Fmt = Fmt.AUTO,     // 数值块：0 / 空时写什么；倍速、列表的写法
)
data class Page(val route: String, val title: String, val blocks: List<Block>, val note: String? = null)
```

模型里提供这些函数，两端共用：

- **active / changed**：是否生效；数值块是否和默认不同。
- **label**：数值块把 `{v}` 换成当前值。
- **step**：点一下要写的值。
- **tappable**：能不能点。
- **operable**：在示意图里就能改完的设置（列表里不用重复）。
- **count**：改了几处。

## 4. 交互规则

- **点一下**：
  - 开关取反；多选加减这一项；单选选上这一项，再点已选的就回到默认（示意图里通常不画“跟随”那项）。
  - 有常用值的数值换到下一个，选项不多（≤5）的单选循环。
- **点不能直接切换的块**（名单、文字、没有常用值的数值、选项很多的单选）：弹出这一项的完整编辑控件。
- **长按任何块**：弹出这一项的说明和完整控件，补上示意图里省掉的解释文字。
- **依赖总开关的块**：总开关关着时不算生效；点它会把总开关一起打开（点了就要看到效果）。
- **上下限**：越界的点击不改（“至少保留一个场景”“最多 4 个分区”）。
- **联动闪烁**：在列表里改了某项，示意图里对应的块闪一下，让人知道它管的是哪里。
- **计数**：“改了 N 处”只算和默认不一样的；默认就开着的不算。
- **关着的开关**：块后面淡淡写出开了会怎样（“所有地址 · 都换到固定节点”），不然只看到一个名字，不知道点了会怎样。
- **会替账号操作的功能**（自动点赞、自动投币…）：标明“用你的账号”。测试时绝不打开。

## 5. 信息密度（高效）

- **默认“示意图”视图，可切“列表”**：全局一个选择，记在本机。
  - 示意图视图里，**有自己块的设置不在列表里重复**。
  - 只以“依赖的总开关”身份出现的设置要留在列表里，否则关不掉。
  - 专门的选择器（照真实界面画的底栏条、颜色色板）和跳转行不收。
- **卡片头一行**：标题 · 一句说明 · 右边“改了 N 处”或“点块改 · 长按看说明”。**图例不要每张卡重复。**
- **紧凑尺寸**（手机）：块最小高度 30dp（浮层 26），内边距 7×3dp，间距 4dp，分组内边距 7×5dp，圆角 7dp。
- **宿主设置窗**同样处理：收起 operable 的项，留一行“示意图里能点的 N 项没列出 · 列出来”。
- **数值块文字要像句子**：“最低播放量 不限”“屏蔽词 3 条”“底栏隐藏 无”。
  - 不要写成“藏了 没藏”“播放量低于 不限 藏”。
  - 0 和空的写法用 `zero` 参数给。

## 6. 隐私

- 凭据（密钥、令牌、密码）只显示“已设置 / 未设置”。
- 网址只显示主机，去掉路径、查询和 `user:pass@`。
- 样例和日志不带账号信息。
- 用单测锁住：把一个带密钥、带 `token:secret@` 的值喂进去，断言显示出来的字里不含它们。

## 7. 用测试保证“全部都做了”

公共模块里至少写这些单测，并接进构建门禁：

1. **覆盖**：每一项用户设置（排除内部和“即将支持”）都出现在某张示意图的绑定里（自己的块或 `requires`）。失败时列出“哪项 → 属于哪页”。
2. **绑定合法**：
   - 绑定的设置真实存在。
   - 开关不带选项，多选和单选的选项都在选项表里，数值块不带选项。
   - 同一页里一个绑定只出现一次。
3. **一页一图**：路由不重复。另用 grep 核对每个路由都在对应页面里真的渲染了。
4. **专题清单一致**：比如“去广告”清单和去广告示意图的绑定集合完全相等。
5. **交互**：总开关联动、单选再点回默认、计数只算改动、凭据不外露。

## 8. 落地流程

1. 盘点脚本 → 缺口清单（按页）。
2. 每页设计示意图：先结构，再逐项绑定，按第 1 节选画法。
3. 两端渲染，接上第 4 节的交互和第 5 节的密度规则。
4. 单测全绿，再过门禁（lint 当错误）。
5. **真机检查**：
   - 逐页截图，拼成四联图一起看。
   - 点一块，确认设置真的写进去；再点一下恢复原值。
   - 长按，确认弹出说明。
   - 宿主设置窗也看一遍。
   - 测试时临时改的开关，测完都改回去。
6. 复查一遍：重新跑盘点，确认缺口为 0，再看密度（大多数页面一屏看完）。

## 9. 踩过的坑

- **对象初始化顺序**（Kotlin `object`）：页面列表引用的快捷变量必须声明在列表之前，否则初始化时是 null。
- **“即将支持”的功能**：不要画成能点的块，免得误导。
- **宿主列表的收起**：单选不能因为示意图里画了部分选项就收起，否则改不回“跟随”。只收 operable 判定为“能改完”的项。
- **示意图里的单选不画默认项时**：一定要支持“再点回到默认”。
- **示意图只描述结构**：选项名直接用设置里的选项表，和目标界面的叫法保持一致，不要手抄第二份。
- **采样功能**：要注册在所有过滤功能前面，看到的才是原始数据；只读不改。
